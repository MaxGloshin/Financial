## 1. Принципы планирования

1. **Сначала деньги, потом красота.** Ядро учёта и инварианты — до анимаций.
2. **Каждый этап заканчивается работающим приложением.** Никаких «полуготовых» веток на месяц.
3. **Локально = production по коду.** Одна кодовая база, различия только в конфиге.
4. **Никакой инфраструктуры до согласия.** Локальный SQLite, локальные бэкапы, `localhost`.
5. **Не автоматизировать то, что ещё не стабильно.** Shortcuts/SMS — после ручного ввода.
6. **Безопасность не «в конце».** Passkey, сессии, замок и коды восстановления — в первом этапе.
7. **Один этап — один проверяемый результат.** Тесты и демонстрация, а не «почти готово».

## 2. Границы MVP

### Входит

- Вход по passkey, второй passkey, коды восстановления, устройства и сессии.
- Блокировка приложения после 15 минут неактивности (настраивается), разблокировка WebAuthn.
- Счета: наличные, дебет, кредитка, долг мне, неликвид (Steam — отдельно).
- Операции: расход, доход, перевод, погашение кредитки, возврат долга, корректировка.
- Двойная запись, целые копейки, undo, история изменений.
- Быстрый ввод: открыть → сумма → категория → сохранить; шаблоны в один тап.
- Кредитка: лимит, долг, выписка, даты, предупреждения, «сумма неизвестна».
- Бюджет: водопад, «безопасно сегодня», план/факт; 6 000 ₽ — редактируемый ориентир.
- Финансовый помощник: безопасный остаток, прогноз до гарантированного дохода, предупреждения, оценка покупки, распределение нерегулярного дохода, объяснение расчётов.
- Аналитика: доходы/расходы, категории, динамика долга, простой прогноз.
- Автоматические шифрованные бэкапы + проверка восстановления.
- PWA: установка, офлайн, тёмная тема, safe areas.
- Воспроизводимый тест Apple Shortcuts (без SMS-интеграции и без оплаты).

### Не входит в MVP (v1.1+)

- SMS-интеграция и платная услуга банка.
- CSV-импорт (правила дедупликации зафиксированы заранее, реализация позже).
- Push-напоминания.
- Голосовой шорткат как рабочий канал (сначала тест).
- Шифрование локального кэша PIN-кодом.
- Мультивалютность.
- Подработки и цели в полном виде (поля в модели есть).

> Кредитка и пенсия — исключение: они нужны с первого дня, иначе приложение не отражает реальность.

## 3. Этапы

### Этап 0. Локальный каркас (0.5–1 день) — **выполнен**

- Репозиторий, `.gitignore`, `.env.example`, `.env.local`.
- Монорепо: `server/`, `web/`, `scripts/`, `docs/`.
- Node.js + встроенный `node:sqlite` (без нативной сборки).
- Fastify API, Vite SPA, прокси `/api` → API.
- Миграции SQL, `schema_migrations`.
- `GET /api/health`, проверка конфигурации при старте.
- Тесты: `node:test`.

**Готово, когда:** `npm run dev` поднимает API и UI, `/api/health` отвечает 200, тесты запускаются. *(Выполнено.)*

---

### Этап 1. Аутентификация, восстановление, замок (2–3 дня) — **выполнен**

- Passkey-регистрация и вход (`@simplewebauthn/server`).
- `rp_id` хранится в каждой записи passkey.
- Сессии в HttpOnly-cookie: `pf_sid` локально, `__Host-pf_sid` в production.
- Список passkeys и устройств, отзыв сессии.
- Второй passkey на другом устройстве (кнопка «Добавить ключ»).
- 10 одноразовых кодов восстановления (scrypt), вход по коду.
- Setup-токен, `/setup` закрывается после настройки.
- Блокировка: таймаут 15 минут, разблокировка WebAuthn, без промпта при каждом открытии.
- Rate limit, Origin-check, security headers, CSP.
- Каркас SPA: роутинг, темы, нижняя навигация.

**Готово, когда:** вход с iPhone и Windows; перезапуск сохраняет сессию; отзыв устройства работает; повторный `/setup` → 404; вход по коду создаёт новый passkey; замок срабатывает после таймаута и не срабатывает при коротком возврате. *(Выполнено локально.)*

---

### Этап 2. Денежное ядро (4–6 дней) — **выполнен**

- Схема: `accounts`, `categories`, `transactions`, `ledger_entries`.
- Доменный слой: создание операции → сбалансированные проводки.
- Инварианты: сумма = 0, XOR account/category, запрет float.
- CRUD операций, soft-delete, undo (восстановление), аудит.
- Шаблоны: создание, применение в один тап, счётчик использования.
- Сид стартовых данных с датами и флагами.
- Помощник: безопасный остаток, прогноз, оценка покупки, распределение, объяснение.
- Экраны: главная, операции, детали, счета, помощник, настройки.
- Тесты: деньги, инварианты, API, помощник, бэкапы.

**Готово, когда:** расход/доход/перевод/погашение корректно меняют балансы; перевод не попадает в доходы/расходы; undo возвращает состояние; шаблон создаёт операцию; помощник не учитывает подарок и кредитный лимит; бэкап восстанавливается. *(Выполнено локально, см. отчёт.)*

**→ После этапа 2 — остановка, тесты, демонстрация, список рисков.**

---

### Этап 3. Офлайн и синхронизация (5–7 дней)

- IndexedDB (Dexie): сущности, курсор, `outbox`.
- Оптимистичные мутации, статусы pending/synced/failed.
- `POST /api/sync/push` с идемпотентностью (`applied_ops`).
- `GET /api/sync/pull` по `changes.seq`.
- `GET /api/sync/snapshot` для нового устройства.
- Разрешение конфликтов: авто для неденежных, ручное для денежных.
- Индикаторы: офлайн, очередь, ошибка, конфликт.
- E2E: два контекста, офлайн-создание, восстановление сети.

**Готово, когда:** операция, созданная офлайн, доезжает ровно один раз; повторная отправка не создаёт дубль; конфликт показывается; новое устройство получает полное состояние.

---

### Этап 4. Кредитка и выписки (3–4 дня)

- Поля кредитного счёта, доступный лимит.
- `credit_statements`, ручное создание, статусы.
- `grace_end_date` как отдельное поле, `NULL` допустим.
- Предупреждения: срок < 7 дней, сумма неизвестна, льгота не подтверждена.
- Погашение как перевод, не расход.
- Прогноз долга.
- Экран кредитки.

**Готово, когда:** погашение уменьшает долг и не увеличивает расходы; неизвестная сумма отображается как «не указана»; предупреждение появляется за 7 дней.

---

### Этап 5. Бюджет и аналитика (4–5 дней)

- Водопад распределения (доход → обязательные → кредит → резерв → свободно).
- «Безопасно сегодня/на неделю».
- План/факт по категориям, перерасход.
- Аналитика: периоды, категории, динамика долга, прогноз остатка.
- Явная маркировка предположений (подарок не учитывается).
- Экспорт CSV/JSON.

**Готово, когда:** числа сходятся с ручным расчётом на тестовом наборе; «безопасно сегодня» никогда не учитывает кредитный лимит и возможный подарок; перерасход виден.

**→ MVP готов.**

---

### Этап 6. Подработки и цели (3–4 дня)

- Проекты: выручка, себестоимость, материалы, прибыль, статусы.
- Связь операций с проектом, маржа.
- Ожидаемые поступления (не в балансе).
- Цели: целевая сумма, дата, прогресс, взносы.
- Экраны проектов и целей.

**Готово, когда:** флешка за 2 000 при затратах 700 показывает 1 300 прибыли; незавершённый заказ не увеличивает баланс.

---

### Этап 7. Автоматизация ввода (4–6 дней)

Сначала — **воспроизводимый тест Shortcuts**, затем решение о SMS.

- `tools/shortcut-probe/` — локальный приёмник для проверки шортката на реальном iPhone.
- Инструкция `docs/SHORTCUTS-TEST.md`: триггер SMS, диктовка, ручной запуск.
- Проверка: что Shortcuts реально получает от SMS; что не получает от push; что происходит без разблокировки.
- `/api/ingest/text` — парсер «кофе 250», числительные, словарь категорий.
- `/api/ingest/sms` — только после теста и отдельного решения об оплате.
- Токены устройств: создание, отзыв, аудит.
- `/api/ingest/csv` — загрузка, профили банков, предпросмотр, коммит.
- Дедупликация и сверка импорта.
- Фикстуры: обезличенные SMS и CSV.

**Готово, когда:** тест Shortcuts воспроизводится на iPhone; неизвестный формат SMS уходит в инбокс, а не создаёт мусор; повторный импорт того же CSV не создаёт дублей; ручная и импортированная операция не учитываются дважды.

## 5. Тестовая стратегия

### 5.1. Юнит-тесты (`node:test`)

- Парсинг денег: `"1 234,56"` → 123456; `"250"` → 25000; мусор → ошибка.
- Форматирование: `123456` → `1 234,56 ₽`.
- Водопад бюджета и помощника: 0, отрицательный, резерв больше дохода.
- Окна дат: пенсия 21–31, конец месяца, високосный год.
- Парсеры SMS/текста (позже): корпус фикстур.
- CSV-профили (позже): обезличенные файлы.

### 5.2. Property-based (без внешних зависимостей)

- Для любой операции: `SUM(entries) = 0`.
- Для любой последовательности операций: баланс = начальный + сумма проводок.
- Перевод не меняет сумму доходов и расходов.
- Погашение кредитки не меняет сумму расходов.
- Undo после любой операции возвращает исходное состояние.
- Детерминизм помощника: одинаковые входы → одинаковые выходы.

### 5.3. Интеграционные (in-memory SQLite)

- Регистрация/вход passkey (мок-ассерция на уровне домена).
- Истечение сессии, отзыв.
- Rate limit.
- Push: применение, дубликат, конфликт, отклонение.
- Pull: курсор, пагинация, snapshot.
- Импорт: дубли, неизвестные колонки, битые строки.

### 5.4. E2E (Playwright, Chromium + WebKit) — после этапа 3

- Онбординг → главная.
- Быстрый ввод за 3 действия.
- Офлайн: `context.setOffline(true)` → создать → `false` → проверить отправку.
- Два контекста (два «устройства») → синхронизация.
- Конфликт: изменить на одном, потом на другом → экран сравнения.
- Кредитка: погашение не меняет расходы.
- Импорт CSV: предпросмотр и отсутствие дублей.
- Тёмная тема, мобильный viewport 390×844.

### 5.5. Ручные проверки на устройстве

| # | Проверка |
|---|---|
| 1 | Установка на домашний экран, сессия сохраняется |
| 2 | Passkey создаётся и используется после перезапуска |
| 3 | Второй passkey на Windows |
| 4 | Офлайн-создание и отправка (после этапа 3) |
| 5 | Push после установки |
| 6 | Safe areas, нижняя навигация |
| 7 | Клавиатура в быстром вводе |
| 8 | Тёмная тема |
| 9 | Share sheet экспорта |
| 10 | Shortcut-тест (SMS/диктовка) |
| 11 | Блокировка после 15 минут и разблокировка Face ID |
| 12 | Восстановление по коду |
| 13 | Шаблон в один тап + Undo |
| 14 | Бэкап и восстановление на ПК |
| 15 | Второй passkey удаляет страх потери устройства |

### 5.6. Безопасность

- Проверка заголовков (CSP, HSTS) в CI.
- Тест: cookie недоступна из JS.
- Тест: запрос без Origin отклонён.
- Тест: ingest-токен не может читать (после этапа 7).
- `npm audit` + Dependabot.
- Ручной проход по чек-листу `SECURITY.md` перед каждым релизом.

### 5.7. Данные

- Golden-набор: 3 месяца операций, известные итоги.
- Каждый релиз: прогон отчётов на golden-наборе, сверка чисел.
- Restore-тест бэкапа — ежемесячно.

## 6. Безопасный деплой

### 6.1. Сейчас (локально)

```
npm run dev        # API + UI, только localhost
npm test           # домен, API, помощник, бэкапы
npm run build      # сборка SPA
npm run backup     # шифрованный архив в ./backups
npm run verify-backup
```

- Наружу ничего не публикуется.
- `APP_ENV=local`, RP ID `localhost`.
- Демо-режим (если включён) работает только на loopback и только с токеном.

### 6.2. Позже (VPS, после согласия)

```
1. Push в main → CI
2. lint + typecheck + unit + integration
3. Сборка Docker-образа, тег = git sha
4. Деплой на staging (отдельная БД)
5. Smoke-тест staging
6. Тег → деплой на прод:
   a. litestream snapshot
   b. docker compose pull
   c. миграции (в транзакции)
   d. рестарт
   e. /api/health
7. При провале — откат на предыдущий тег + restore snapshot
```

Правила:
- Миграции только вперёд, совместимые с предыдущей версией кода.
- Бэкап перед каждой миграцией.
- Никаких «быстрых правок на сервере».
- Домен `.ru` и TLS — только после покупки и согласия.
- Смена RP ID — через коды восстановления, не автоматически.

## 8. Риски и что делать

| Риск | Признак | Действие |
|---|---|---|
| Синхронизация сложнее, чем кажется | Конфликты в тестах, дубли | Остановиться, упростить: один писатель на устройство, больше ручных разрешений |
| Passkey не работает в установленном PWA | Вход циклится | Fallback: пароль + TOTP на своём origin (не OAuth) |
| Потеря всех passkey и кодов | Нет входа | Данные целы, доступ только через SSH к серверу; поэтому второй passkey обязателен |
| VPS недоступен из РФ (позже) | Таймауты | Сменить провайдера/локацию, проверить до покупки |
| Бюджет не сходится с реальностью | Числа не совпадают | Показывать водопад, дать ручную корректировку, не прятать |
| Слишком много времени на UI | Этап 3+ затягивается | Заморозить визуал, доделать функциональность |
| SMS-формат изменился | Парсер падает | Инбокс вместо операции, фикстуры, быстрый фикс |
| Демо-режим попадёт в production | Открытый вход без passkey | Конфиг запрещает `DEMO_MODE` при `APP_ENV=production`; проверка в тестах |
| Потеря интереса | Нет коммитов 2 недели | MVP уже полезен; автоматизация — опционально |

7. Шифрование локального кэша.
8. Мультивалютность (если появится).
9. Годовой обзор.

---

## 11. Что не делаем никогда

- Публичную регистрацию и многопользовательскость.
- Хранение пароля от интернет-банка.
- Неофициальные API банка.
- Стороннюю аналитику.
- Платные ИИ-API для категоризации.
- Автоматическое «угадывание» денежных сумм без подтверждения.
- Красивые графики, которые не сходятся с балансом.
- Публикацию приложения без явного согласия пользователя.
