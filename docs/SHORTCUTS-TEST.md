# SHORTCUTS-TEST — воспроизводимый тест Apple Shortcuts

> Цель: **до** реализации SMS-интеграции и **до** оплаты услуги банка проверить на реальном iPhone, что именно получает Shortcuts и где автоматизация ломается.
> Ничего не публикуется в интернет. Приёмник работает в локальной сети.

---

## 1. Что проверяем

| # | Гипотеза | Как проверяем |
|---|---|---|
| 1 | Shortcuts может отправить текст в локальный HTTP-сервер | ручной шорткат |
| 2 | Диктовка распознаёт сумму и категорию | шорткат с `Dictate Text` |
| 3 | Автоматизация «When I receive a message» срабатывает на SMS банка | реальное SMS |
| 4 | Автоматизация не срабатывает на push-уведомление | push от банка |
| 5 | Автоматизация работает при заблокированном экране | тест с блокировкой |
| 6 | В тексте сообщения есть сумма, дата, место | лог приёмника |
| 7 | Автоматизация не дублирует сообщение | два одинаковых SMS |
| 8 | Shortcuts не требует подтверждения при «Run Immediately» | наблюдение |

**Важно:** если банк присылает push, а не SMS, тест №3 не пройдёт — и это ожидаемый результат, а не баг приложения. У Т-Банка по умолчанию push; SMS обо всех операциях — платная услуга (99 ₽/мес, 59 ₽ с Т-Мобайл). Бесплатны только security-SMS (коды), они не содержат операций.

## 2. Приёмник

Файл: `tools/shortcut-probe/server.mjs`.

```bash
node tools/shortcut-probe/server.mjs
```

Сервер:

- слушает `0.0.0.0:8787`;
- печатает адреса для iPhone (LAN IP);
- принимает `POST /sms`, `POST /text`, `GET /health`;
- пишет всё в `tools/shortcut-probe/probe-log.jsonl`;
- отвечает `{ "ok": true, "received": {...} }`;
- не требует токена (только локальная сеть, тестовый режим).

Остановка — `Ctrl+C`.

> Windows Firewall может спросить разрешение для Node.js. Разрешить только для **частных сетей**.

## 3. Шорткат A. Ручная отправка

1. Открыть **Shortcuts** → `+` → название `PF Probe`.
2. Добавить действие **Get Contents of URL**.
3. URL: `http://<LAN-IP>:8787/sms`.
4. Раскрыть **Show More**:
   - Method: `POST`
   - Request Body: `JSON`
   - Добавить поле `text` (Text) = `Тест из Shortcuts`.
   - Добавить поле `sender` = `manual`.
5. Запустить.
6. Ожидаемо: в консоли приёмника появляется строка, в Shortcuts — ответ `{"ok":true,...}`.

Если не работает:

- iPhone и ПК в одной сети? (не гостевой Wi-Fi с изоляцией клиентов)
- IP правильный? (не `127.0.0.1`)
- Firewall?
- URL начинается с `http://`, не `https://`?

---

## 4. Шорткат B. Диктовка

1. Новый шорткат `PF Voice`.
2. **Dictate Text** → язык русский.
3. **Get Contents of URL** → `POST http://<LAN-IP>:8787/text`, JSON:
   - `text` = `Dictated Text`
4. **Show Result** (или `Show Notification`) с ответом сервера.
5. Запустить, сказать: «кофе двести пятьдесят».
6. Ожидаемо: в логе `{"text":"кофе двести пятьдесят"}`.

Проверить фразы:

- «кофе двести пятьдесят»
- «потратил тысячу двести на продукты»
- «проезд шестьдесят»
- «получил пенсию тринадцать тысяч»
- «купил флешку за две тысячи, себестоимость семьсот»

Цель — понять, какие формулировки распознаются стабильно, а какие требуют ручной правки. Это исходные данные для парсера, а не готовый парсер.

---

## 5. Шорткат C. Автоматизация на SMS

1. **Shortcuts** → вкладка **Automation** → `+`.
2. Триггер **Message**.
3. Условия:
   - Sender: `Т-Банк` (или короткий номер, который реально приходит);
   - Message Contains: `Покупка` / `Оплата` (подобрать по реальному SMS).
4. **Run Immediately** (не «Ask Before Running»).
5. Действие **Get Contents of URL** → `POST http://<LAN-IP>:8787/sms`, JSON:
   - `text` = `Shortcut Input` (в автоматизации Message это текст сообщения; если поле недоступно — `Shortcut Input` как есть);
   - `sender` = `Shortcut Input` (или фиксированная строка).
6. Сохранить.
7. Попросить кого-то отправить SMS с текстом, похожим на банковский, или дождаться реальной операции.
8. Проверить лог.

### Что может пойти не так

| Симптом | Причина | Что делать |
|---|---|---|
| Автоматизация не сработала | Банк прислал push, не SMS | Это ограничение, не баг. SMS — платная опция |
| Сработала, но текст пустой | Неверно выбран `Shortcut Input` | Пересобрать действие, проверить поля |
| Сработала дважды | SMS пришло дважды / iMessage + SMS | Дедупликация на сервере обязательна |
| Не сработала при заблокированном экране | iOS ограничивает сеть/автоматизации | Проверить с разблокированным; зафиксировать результат |
| «Ask Before Running» | Автоматизация не переведена в Run Immediately | Переключить, но помнить: это меньше контроля |
| Нет доступа к сети | Локальный HTTP при заблокированном экране | Для production нужен HTTPS и внешний сервер |

### Проверка push

1. Отключить SMS-уведомления банка, оставить push.
2. Совершить покупку.
3. Убедиться, что автоматизация **не** сработала.
4. Вывод: push нельзя читать через Shortcuts. Это не решается настройками приложения.

## 6. Формат ответа приёмника

```json
{
  "ok": true,
  "received": {
    "kind": "sms",
    "text": "Покупка 250.00 RUB. Пятёрочка. Баланс 3 750.00 RUB",
    "sender": "Т-Банк",
    "at": "2026-11-21T14:32:10.000Z",
    "remote": "192.168.1.42"
  }
}
```

В production приёмник будет возвращать:

```json
{
  "ok": true,
  "status": "created",
  "transactionId": "...",
  "needsReview": false,
  "summary": "Кофе · 250 ₽"
}
```

или

```json
{
  "ok": true,
  "status": "needs_review",
  "reason": "Не удалось определить категорию",
  "inboxId": "..."
}
```

Шорткат показывает уведомление с `summary` или `reason`. Молча ничего не создаётся.

## 7. Политика подтверждения (предложение)

| Уверенность парсера | Поведение |
|---|---|
| Сумма + счёт + категория определены, формат известен | Создать операцию, показать уведомление с «Отменить» |
| Сумма определена, категория нет | Создать с «Другое», `needs_review` |
| Сумма не определена / формат неизвестен | Не создавать. Сохранить сырой текст в «Инбокс», уведомить |
| Похоже на дубль ручной операции | Не создавать. Показать «Возможный дубль» |

Первые две недели после включения SMS — **все** операции в «Требует проверки», без автосоздания. Это снижает риск тихой ошибки, пока формат не подтверждён на реальных сообщениях.

## 8. Ограничения, которые нельзя обойти

- Нет фонового выполнения на iOS: автоматизация срабатывает по событию, но приложение не работает постоянно.
- Нет чтения push-уведомлений.
- Нет доступа к SMS через веб-приложение: только через Shortcuts.
- Shortcuts не имеет защищённого хранилища секретов: токен лежит в шорткате. Поэтому токен будет write-only, привязан к устройству и отзываем.
- Локальный HTTP не работает вне одной сети; production требует HTTPS и домен.
- При выключенном телефоне и до первой разблокировки после перезагрузки автоматизации не выполняются.

---

## 9. Критерий готовности теста

- [ ] Ручной POST доходит до приёмника.
- [ ] Диктовка распознаёт 5 контрольных фраз (хотя бы 4 из 5).
- [ ] SMS-автоматизация срабатывает на реальное SMS (или зафиксировано, что банк шлёт только push).
- [ ] Push не срабатывает — подтверждено.
- [ ] Поведение при заблокированном экране зафиксировано.
- [ ] Лог сохранён и обезличен (суммы можно оставить, имена/номера — убрать).
- [ ] Принято решение: нужна ли платная SMS-услуга.

После этого — отдельное решение о реализации `/api/ingest/sms` и оплате 99 ₽/мес.
