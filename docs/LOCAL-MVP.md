# LOCAL-MVP — что реализовано (этап 1)

> Дата: 23.11.2026. Это актуальное описание локального приложения.
> Серверные документы (`ARCHITECTURE.md`, `SECURITY.md`, `ROADMAP.md`) сохранены как
> справочник исходного серверного плана; локальная схема ниже имеет приоритет.

---

## 1. Архитектура

```
web/src/
  domain/     бизнес-логика без React: типы, деньги, расчёты, проводки
  db/         Dexie/IndexedDB: схема, транзакции, бэкап, онбординг, демо
  lib/        утилиты: формат/разбор денег, калькулятор выражений, даты, base64
  components/ UI-примитивы (shadcn-стиль без Radix) + экраны-компоненты
  pages/      страницы: обзор, операции, счета, долги, бюджет, цели, настройки, онбординг
  state/      React-контекст: live-снапшот Dexie, тема, быстрый ввод
  test/       тестовые хелперы (fake-indexeddb)
```

Принципы:

- **UI ≠ логика ≠ хранение.** `domain/` ничего не знает про React и Dexie; `db/` не содержит расчётов.
- Деньги — **целые копейки** (`amountMinor`), никакого `float`.
- Стек: React 19 + TypeScript + Vite 8 + Tailwind 4 + Dexie 4 + vite-plugin-pwa + Vitest. Без Radix, без бэкенда.

## 2. Модель данных

Все таблицы в одной Dexie-базе, версии и миграции в `db/db.ts`:

| Таблица | Назначение |
|---|---|
| `accounts` | счета; `openingBalanceMinor` — стартовый остаток; кредитка хранит **отрицательный** баланс и `creditLimitMinor` |
| `categories` | категории, системные + пользовательские |
| `transactions` | операции; мягкое удаление (`deletedAt`), `rev` для оптимистических правок |
| `entries` | проводки (двойная запись): `accountId`/`categoryId`, сумма; **Σ проводок операции = 0** |
| `debts` | долги вне кредитки (`owed_to_me` / `i_owe`), `paidMinor` |
| `goals`, `plannedPayments`, `plannedInflows`, `budgets` | планирование; ожидаемые поступления **никогда не входят в баланс** |
| `settings` | одна запись `id: 'app'`: бюджет по умолчанию, тема, онбординг, `lastBackupAt` |
| `audit` | журнал изменений для истории |

Ключевые правила:

- **Баланс = стартовый остаток + проводки неудалённых операций.** Балансы выводятся на лету (`domain/finance.ts → computeBalances`), поэтому расхождение невозможно.
- **Идемпотентность:** уникальный индекс `&clientRequestId`; повторный ввод не создаёт дубль.
- **Виды операций:** `expense`, `income`, `transfer`, `credit_payment`, `debt_payment`, `refund`, `adjustment`. Правила проводок — в `domain/postings.ts`.
- Перевод/погашение кредитки двигают деньги между счетами, но **не создают доход/расход**.
- Погашение долга меняет `debts.paidMinor` и откатывается при удалении/undo операции.

## 3. Финансовые расчёты (`domain/finance.ts`)

- `moneyOverview`: свои деньги = наличные + дебет + накопления + баланс кредитки (кредитный лимит **не** входит); отдельно долг/доступный лимит кредитки, мне должны/я должен, чистый капитал.
- `monthSummary`: доходы/расходы/возвраты, разбивка по категориям, бюджет (месячный или общий), доступный бюджет, средний расход в день, прогноз до конца месяца. **Возвраты уменьшают netto-расходы** бюджета и прогноза, но не считаются доходом.
- `forecast`: прогноз баланса до ближайшего поступления, «хватит ли денег», предупреждение о ближайшем платеже.
- `purchaseAssessment`: можно ли купить — с учётом обязательных платежей до следующего поступления; кредитный лимит не считается деньгами.
- `upcomingPayments`/`nearestPayment`: плановые платежи + платёж по кредитке.

## 4. Резервные копии (`db/backup.ts`)

- Формат v1: `personal-finance-backup` с `formatVersion`, `appVersion`, `exportedAt`, `counts`, `data`, `checksum`.
- **Контрольная сумма** — SHA-256 от канонического JSON (`stableStringify`: отсортированные ключи), поэтому пере-валидация распарсенного файла не даёт ложных отказов (регрессия исправлена и покрыта тестом).
- Валидация: zod-схемы всех записей → сверка `counts` → ссылочная целостность (счета/категории/операции/долги).
- Импорт: `replace` (полная замена) и `merge` (пропуск существующих ID и `clientRequestId`), с отчётом `added/skipped/warnings`.
- **Шифрование** (по желанию): PBKDF2-SHA256, 210 000 итераций + AES-GCM 256; пароль не хранится и никуда не отправляется; забыт — копия не восстанавливается.
- Статус копии: «нет копии» / возраст в днях; предупреждение в настройках и на обзоре, если копии нет или ей больше 7 дней.
- Экспорт на iPhone: «Скачать JSON» → Safari → «Сохранить в Файлы».

## 5. PWA и офлайн

- `vite-plugin-pwa` (generateSW, precache всех ассетов), `registerType: 'prompt'` — обновление применяется только после подтверждения пользователем; IndexedDB переживает обновления.
- `HashRouter` — навигация не зависит от серверных rewrite (важно для GitHub Pages).
- `VITE_BASE` задаёт базовый путь: локально `/`, на Pages `/<repo>/` (проставляет deploy-workflow).
- Манифест: standalone, RU, иконки 192/512 + maskable (генерируются `npm run icons` без внешних зависимостей).
- `.nojekyll` в `web/public` — ассеты с подчёркиваниями не режутся Jekyll'ом.
