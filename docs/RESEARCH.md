## 1. iOS PWA: что реально работает в 2026

### 1.1. Установка и запуск

| Возможность | Статус | Детали |
|---|---|---|
| Добавление на домашний экран | ✅ | Вручную: «Поделиться» → «На экран "Домой"». Автоматического промпта нет, `beforeinstallprompt` не поддерживается |
| Запуск в отдельном окне | ✅ | С iOS 26 любая добавленная на экран сайт-ссылка по умолчанию открывается как веб-приложение (можно отключить «Открыть как веб-приложение») |
| Своё хранилище у установленного приложения | ✅ | Отдельный контейнер: cookies, IndexedDB, Cache Storage, permissions. С iOS 17.2 cookies копируются из Safari при установке, остальное — нет |
| Иконка, splash, статус-бар | ✅ | Через manifest + apple-touch-icon. Splash — apple-touch-startup-image |
| Ярлыки при долгом нажатии на иконку | ❌ | `manifest.shortcuts` на iOS не поддерживается |
| Deep link в приложение | ⚠️ | Открытие URL внутри scope работает. Внешние ссылки (из письма, из другого приложения) открываются в Safari, не в установленном приложении |

**Вывод:** установка — ручное действие пользователя. Онбординг обязан объяснять шаги и не обещать автоматический промпт.

### 1.2. Офлайн и хранилище

| Возможность | Статус | Детали |
|---|---|---|
| Service Worker + Cache API | ✅ | С iOS 11.3. База офлайн-режима |
| IndexedDB | ✅ | Работает, отдельная БД на контекст |
| OPFS | ✅ | С iOS 15.2 |
| Квота | ✅ | С iOS 17 — до ~60% диска на origin, как в браузере. Установленное приложение — та же квота |
| `navigator.storage.persist()` | ✅ | С iOS 15.2. Решение принимает WebKit эвристически (учитывает, запущено ли приложение с домашнего экрана), диалога нет |
| Вытеснение данных | ✅ | Возможно при переполнении общей квоты, нехватке места, долгом неиспользовании. Persistent-режим исключает origin из вытеснения |
| «Правило 7 дней» | ✅ | Относится к script-writable storage в Safari-вкладках (ITP). У установленных веб-приложений свой счётчик использования, обычная работа его сбрасывает |
| Background Sync | ❌ | Не реализовано |
| Periodic Background Sync | ❌ | Не реализовано |
| Background Fetch | ❌ | Не реализовано |

**Критический вывод:** на iOS **нет фоновой синхронизации**. Очередь операций отправляется только пока приложение открыто: при запуске, при возврате из фона, по событию `online`. Проектировать «отправится само, даже если приложение закрыто» нельзя.

**Следствие для архитектуры:** локальные данные — не единственная копия. Сервер — источник истины, плюс обязательный экспорт. Потеря локального кэша не должна означать потерю денежной истории.

### 1.3. Уведомления

| Возможность | Статус | Детали |
|---|---|---|
| Web Push | ✅ | С iOS 16.4, **только** для приложений с домашнего экрана. Разрешение запрашивается только по тапу пользователя |
| Silent push | ❌ | `userVisibleOnly: true` обязателен; каждый push обязан показать уведомление, иначе подписка отзывается |
| Declarative Web Push | ✅ | С iOS 18.4, без service worker для показа уведомления |
| Badging API | ✅ | С iOS 16.4, только установленное приложение |
| Кнопки действий на уведомлении | ❌ | Не поддерживаются в Safari |
| Локальные запланированные уведомления | ❌ | Нет API. Напоминание о платеже — либо серверный push, либо Shortcuts-автоматизация по времени |

**Вывод:** напоминание «платёж по кредитке 22 декабря» реализуется серверным push (бесплатно, VAPID) с fallback на Shortcuts-автоматизацию «Время дня».

### 1.4. Аутентификация

| Возможность | Статус | Детали |
|---|---|---|
| WebAuthn / passkeys | ✅ | С iOS 13, в установленных веб-приложениях работает |
| Синхронизированные passkeys (iCloud Keychain) | ✅ | С iOS 16 |
| Conditional UI (passkey в автозаполнении) | ✅ | С iOS 16 |
| PRF-расширение (ключ из passkey) | ✅ | С iOS 18; на Windows Hello поддержка частичная |
| OAuth-редирект в установленном приложении | ⚠️ | Провайдер вне scope → возможен выход в Safari. Ненадёжно |

**Вывод:** единственный предсказуемый способ входа в установленном iOS-приложении — **passkey на своём origin** или пароль на своём origin. Всё, что уводит на чужой домен, ломает сессию.

## 2. Apple Shortcuts: что действительно можно

### 2.1. Подтверждённые возможности

| Возможность | Статус | Детали |
|---|---|---|
| Персональная автоматизация по сообщению | ✅ | Триггер «Когда приходит сообщение», условия: отправитель и/или содержит текст. Может выполняться без подтверждения, в том числе на заблокированном экране |
| Условие по отправителю | ⚠️ | Пикер отправителя показывает только контакты. Банковские SMS приходят с буквенных имён (например, `T-Bank`), которых нет в контактах → фильтр по тексту сообщения |
| `Get Contents of URL` с POST/JSON и заголовками | ✅ | Полноценный HTTP-клиент. Заголовок `Authorization` задаётся вручную |
| Regex (`Match Text`, `Get Group from Matched Text`) | ✅ | ICU-регулярки, флаги `(?m)`, `(?s)` |
| Диктовка (`Dictate Text`) | ✅ | Системная, бесплатная, работает офлайн на новых устройствах (зависит от языка/модели) |
| OCR (`Extract Text from Image`) | ✅ | На устройстве, бесплатно, поддерживает русский |
| Share Sheet как вход в шорткат | ✅ | Шорткат может принимать текст, URL, изображения, файлы |
| Кнопка «Действие» (iPhone 15 Pro и новее) | ✅ | Запуск шортката одним физическим нажатием |
| Иконка шортката на домашнем экране | ✅ | Полноценная иконка, открывает шорткат |
| Виджет на экране блокировки | ✅ | Запуск шортката в одно касание |
| Siri | ✅ | «Привет, Siri, добавь расход» |
| Чтение push-уведомлений других приложений | ❌ | Триггера на уведомление нет. Т-Банк по умолчанию присылает push → этот канал недоступен |
| Чтение SMS задним числом | ❌ | Автоматизация реагирует только на новые сообщения |
| Работа при выключенном телефоне | ❌ | Нужен включённый iPhone и сеть |
| Хранение секрета в Keychain | ❌ | Нативного действия нет. Токен хранится в теле шортката |

### 2.2. Практические ограничения Shortcuts

- Нет try/catch: ошибка обрывает выполнение.
- Нет циклов `while`, нет функций, нет асинхронности.
- Одно действие — не более ~30 секунд.
- `Ask for Input` всегда возвращает текст, даже если выбран тип «Число».
- После перезагрузки телефона до первого разблокирования сохранённые секреты недоступны.
- Автоматизация не сработает, если в цепочке есть действие, требующее экрана (compose sheet, выбор из списка).
- Шорткаты синхронизируются через iCloud → токен в шорткате считается «секретом на устройстве», а не в защищённом хранилище.

**Вывод:** Shortcuts — отличный **транспорт** («взять текст → отправить на сервер»), плохой **мозг** (парсинг, категоризация, правила). Парсинг должен жить на сервере, чтобы его можно было менять без редактирования шортката на телефоне.

## 3. Импорт банковских выписок

### 3.1. Т-Банк

| Канал | Статус | Детали |
|---|---|---|
| CSV-выгрузка операций | ✅ | Доступна **только в компьютерной версии** сайта. В мобильном приложении CSV нет |
| PDF-выписка в приложении | ✅ | Через «Поделиться» / «Выписка по счёту». Есть текстовый слой |
| Excel-выгрузка | ⚠️ | Периодически появлялась/исчезала в веб-интерфейсе. Проверять на реальном аккаунте |
| Официальное API для физлиц | ❌ | «API Физических лиц» — B2B-продукт для фронтенд-систем банка, стоимость индивидуальная. Физлицу не подключается |
| T-API для бизнеса | ❌ | Бесплатно, но требует расчётного счёта ИП/ООО. Не подходит |
| Неофициальный внутренний API (cookies/session) | ❌ | Существуют сторонние read-only обёртки. Нарушает условия банка, требует хранения банковской сессии. **Не используем** |

**Формат CSV** (типичный, требует проверки на реальном файле): разделитель `;`, колонки вида «Дата операции», «Дата платежа», «Номер карты», «Статус», «Сумма операции», «Валюта операции», «Сумма платежа», «Валюта платежа», «Кэшбэк», «Категория», «MCC», «Описание». Импортёр должен быть терпимым к изменениям: сопоставление колонок по заголовкам + ручная правка в предпросмотре.

### 3.2. Другие банки

| Банк | Формат | Комментарий |
|---|---|---|
| Сбер | CSV/Excel из веб-версии, PDF | Столбцы отличаются; нужен отдельный маппинг |
| ВТБ | Excel/PDF | Аналогично |
| Альфа | CSV/Excel | Аналогично |
| Универсальный путь | CSV с ручным маппингом | Один импортёр + профили банков |

**Архитектурное решение:** импортёр не «знает банк», он знает **профиль колонок**. Профиль — конфиг (JSON), проверяемый на фикстурах. Новый банк = новый профиль, без правки ядра.

### 3.3. Чеки ФНС (QR)

- QR-код чека содержит ссылку на `receipt.fns.gov.ru` и параметры.
- Официальный API проверки чеков существует, но требует авторизации/токена и имеет ограничения.
- **Статус: ⚠️ возможная опция, не для MVP.** Для MVP достаточно: QR сканируется камерой телефона → открывается страница чека → пользователь копирует сумму. Или OCR скриншота через Shortcuts.

## 5. Сравнение методов минимизации ручного ввода

Оценки: 1 — плохо, 5 — отлично. «Действий» — осознанные действия пользователя, без учёта набора цифр суммы.

| # | Метод | Доступность iOS | Действий | Безопасность | Цена | Надёжность | Сложность | Итог |
|---|---|---|---|---|---|---|---|---|
| 1 | Быстрый ввод в PWA | ✅ Полная | 2–3 | 5 | 0 | 5 | Низкая | **5.0** |
| 2 | Shortcuts + защищённый API | ✅ Полная | 1 + голос | 4 | 0 | 4 | Средняя | **4.7** |
| 3 | Импорт выписок CSV/PDF | ✅ Полная (CSV — с ПК) | ~8 в месяц | 5 | 0 | 4 | Средняя | **4.2** |
| 4 | Голосовой ввод (системная диктовка) | ✅ Полная | 1 | 4 | 0 | 3 | Низкая | **4.5** |
| 5 | OCR текста операций | ✅ Через Shortcuts | 2–3 | 4 | 0 | 3 | Средняя | **3.6** |
| 6 | Повторяющиеся операции и шаблоны | ✅ Полная | 1 | 5 | 0 | 5 | Низкая | **4.8** |
| 7 | Официальные банковские API | ❌ Нет | — | — | — | — | — | **0** |
| 8 | Share Sheet → PWA | ❌ PWA не может быть целью на iOS | — | — | — | — | — | **0** |
| 8b | Share Sheet → Shortcut | ✅ Работает | 2 | 4 | 0 | 4 | Низкая | **4.0** |
| 9 | Запуск с домашнего экрана | ✅ Иконка PWA / иконка шортката / виджет / Action Button | 0–1 | 5 | 0 | 5 | Низкая | **4.9** |
| 10 | Автоматизация по SMS Т-Банка | ⚠️ Только если включены платные SMS | 0 | 3 | 99 ₽/мес | 3 | Средняя | **3.8** |

### 5.1. Разбор ключевых методов

**PWA-ввод (1).** Открытие с домашнего экрана → «+» → сумма → категория. При запоминании последнего счёта и категории — 2 действия плюс цифры. Работает офлайн. Это база, без неё приложение бессмысленно.

**Shortcuts + API (2).** Одно физическое действие (Action Button / виджет / Siri) → диктовка «кофе двести пятьдесят» → POST на сервер → сервер парсит → уведомление «Записано: Кофе 250 ₽» с возможностью отмены. Это самый быстрый способ ввода, который вообще существует на iPhone без нативного приложения. Ограничение: токен хранится в шорткате, поэтому токен делаем write-only, отдельным на устройство, отзываемым.

**Импорт выписок (3).** Не для ежедневного ввода, а для **сверки**. Раз в месяц: скачать CSV на ПК → загрузить → предпросмотр → импорт. Ловит всё, что забыли записать, и проверяет баланс. Обязателен, потому что ручной ввод всегда имеет пропуски.

**Голос (4).** Системная диктовка бесплатна и точна для коротких фраз. Русские числительные («двести пятьдесят») нужно нормализовать на сервере. Не требует сторонних API.

**OCR (5).** Полезен для чеков и скриншотов. Точность на русских чеках средняя; всегда нужен предпросмотр. Не основной путь.

**Шаблоны (6).** «Проезд 60 ₽», «Обед 300 ₽» — одно касание. Для нерегулярного дохода и повторяющихся трат это даёт непропорционально большой выигрыш.

**Официальные API (7).** Недоступны. Точка.

**Share Sheet (8).** PWA на iOS не может быть получателем шаринга — WebKit не реализовал Web Share Target. Обходной путь: шорткат «Записать расход» появляется в share sheet и принимает текст/картинку. Это работает и является законным путём.

**Домашний экран (9).** Иконка PWA с deep link `?quick=1` открывает сразу клавиатуру суммы. Иконка шортката — ещё быстрее для голоса.

**SMS-автоматизация (10).** Работает, но:
- Т-Банк по умолчанию присылает **push**, а не SMS;
- SMS обо всех операциях — платная услуга **99 ₽/мес** (59 ₽ с сим-картой Т-Мобайла), бесплатны только security-SMS;
- push-уведомления Shortcuts читать не умеет;
- парсинг SMS хрупок: формат меняется, суммы и названия магазинов приходят сокращёнными;
- автоматизация не работает, если телефон выключен или не разблокирован после перезагрузки.

Поэтому SMS-канал — **опция**, а не фундамент. Если пользователь готов платить 99 ₽/мес, он получает ввод с 0 действий. Если нет — голос + PWA закрывают 95% случаев.

### 5.2. Рекомендуемая комбинация

```
Ежедневно, 80% операций:
  PWA quick-add  ────────────────  2–3 действия
  Шаблоны        ────────────────  1 действие
  Голос/Action Button ───────────  1 нажатие + фраза

Регулярно, 15%:
  SMS-автоматизация (опция, 99 ₽/мес) ── 0 действий, но требует проверки
  OCR чека через share sheet ──────────  2–3 действия

Раз в месяц:
  CSV-импорт с ПК ───────────────  сверка и закрытие пробелов
  Повторяющиеся операции ────────  аренда/подписки/пенсия
```

## 6. Хостинг: главный риск — доступность из России

### 6.1. Cloudflare

| Факт | Статус | Детали |
|---|---|---|
| Троттлинг Cloudflare в РФ | ✅ | С 09.06.2025 российские провайдеры (Ростелеком, МТС, Мегафон, Билайн, МГТС) ограничивают трафик к Cloudflare до ~16 КБ на соединение. Официальная документация Cloudflare подтверждает и говорит, что повлиять не может |
| `*.workers.dev` | ⚠️ | Периодически попадает под блокировки РКН. Для продакшена не годится |

## 7. Аутентификация: сравнение

| Вариант | Безопасность | UX в iOS PWA | Стоимость | Сложность | Вердикт |
|---|---|---|---|---|---|
| Cloudflare Access + passkey | 5 | 3 — редирект на чужой домен в установленном приложении | 0 | Очень низкая | Хорош как внешний слой, рискован как единственный |
| Собственный backend + passkey (WebAuthn) | 5 | 5 — всё на своём origin, без редиректов | 0 | Средняя | **Рекомендуется** |
| Пароль + TOTP | 3 | 4 | 0 | Низкая | Фолбэк, не основной |
| Magic link по email | 3 | 1 — ломается в установленном приложении | 0 | Низкая | Отклонить |
| OAuth (Google и т.п.) | 4 | 2 — выход из scope | 0 | Низкая | Отклонить |

**Ключевой факт:** cookies, установленные сервером на своём домене, копируются в установленное iOS-приложение при создании (с iOS 17.2). Passkey живёт в iCloud Keychain и работает и в Safari, и в приложении, потому что RP ID один и тот же. Это делает связку «свой origin + passkey + HttpOnly cookie» самой надёжной.

## 9. Что подтверждено, что гипотеза, что проверить

### Подтверждено (можно проектировать)
- Passkeys работают в установленных iOS PWA на своём домене.
- Web Push работает только в установленном приложении и только с видимым уведомлением.
- Background Sync на iOS отсутствует.
- Web Share Target на iOS отсутствует.
- Shortcuts умеет: триггер по SMS, POST JSON, regex, диктовку, OCR, share sheet, Action Button.
- Shortcuts не умеет читать push-уведомления.
- Т-Банк: CSV только на сайте с ПК; SMS обо всех операциях — платно.
- Официального API для физлиц в РФ нет.
- Cloudflare троттлится в РФ.

### Гипотезы (нужна проверка)
- ⚠️ Точный формат SMS Т-Банка в 2026 (нужен корпус реальных сообщений).
- ⚠️ Точные колонки CSV Т-Банка (нужен реальный файл).
- ⚠️ Стабильность автоматизации Shortcuts на iOS 27 при заблокированном экране.
- ⚠️ Восстановление Access-сессии внутри установленного PWA (если выбирать Cloudflare Access).
- ⚠️ Поведение `persist()` на конкретном iPhone.
- ⚠️ Поддержка PRF на конкретном Windows Hello-устройстве.

### Обязательные тесты на устройстве до реализации
1. Установить тестовое PWA, создать passkey, войти после перезапуска.
2. Проверить, что cookie-сессия переживает установку на домашний экран.
3. Проверить работу офлайн: создать операцию, закрыть приложение, открыть, выйти в сеть.
4. Проверить push после установки.
5. Проверить, что `persist()` возвращает `true` (или хотя бы не падает).
6. Проверить SMS-автоматизацию на реальном сообщении банка.
7. Замерить доступность выбранного хостинга с мобильного интернета и с домашнего Wi-Fi.
