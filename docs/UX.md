# UX — Personal Finance PWA

> Этап C. Сценарии, экраны, прототип, дизайн-система.
> Принцип: **приложение должно быть быстрее, чем блокнот**. Если запись расхода занимает больше 5 секунд, ей не будут пользоваться.

---

## 1. Принципы

1. **Скорость важнее полноты.** Целевой сценарий: открыть PWA → ввести сумму → выбрать категорию → сохранить. Все поля, кроме суммы, имеют значение по умолчанию. Полный редактор — по долгому нажатию.
2. **Одно действие — один экран.** Никаких мастеров из 5 шагов.
3. **Повторяемое — в один тап.** Шаблоны («Проезд 60 ₽», «Кофе 250 ₽») выносятся на главный экран и в лист ввода.
4. **Undo вместо «Вы уверены?».** Подтверждения только для необратимого (удаление passkey, экспорт).
4. **Честность данных.** Если сумма неизвестна — «не указана», а не ноль. Если данные предварительные — «предварительно».
5. **Никаких фиктивных кнопок.** Каждый элемент либо работает, либо отсутствует.
6. **Одна рука.** Основные действия — в нижней трети экрана.
7. **Тишина.** Никаких пушей «вы не записали расход». Только то, что требует действия: платёж, ошибка синхронизации, конфликт.
8. **Замок не мешает.** Приложение не требует PIN/Face ID при каждом открытии: только после 15 минут неактивности (настраивается).

## 2. Контекст использования

| Параметр | Значение |

| Устройства | iPhone (основное), Windows-ноутбук/ПК |
| Ориентация | Портрет на телефоне, широкий экран на ПК |

## 3. Ключевые сценарии

### Сценарий 1. «Кофе за 250 ₽» — 3 действия

```
[Тап по иконке]  →  [Тап «+»]  →  [250]  →  [Тап «Кофе»]
     1 действие      2 действие    цифры      3 действие
```

Что происходит:
- Приложение открывается на главном экране.
- «+» — большая кнопка внизу справа, в зоне большого пальца.
- Открывается нижний лист: клавиатура уже активна, счёт и категория предвыбраны (последние использованные).
- Ввод суммы: крупные цифры, `0–9`, `,`, `⌫`. Сумма показывается крупно.
- Сетка категорий 3×4: «Продукты», «Кафе», «Транспорт», «Дом», «Здоровье», «Связь», «Развлечения», «Одежда», «Подработка», «Долг», «Другое».
- Тап по категории → сохранение, лист закрывается, тост «Записано · 250 ₽ · Кафе» с кнопкой «Отменить» (5 секунд).
- Если сумма введена, но категория не выбрана — кнопка «Сохранить» активна, категория «Другое».
- Сверху листа — горизонтальная лента шаблонов. Тап по шаблону подставляет сумму, счёт и категорию; остаётся нажать «Сохранить».
- Введённая вручную операция сразу доступна для сохранения как шаблон («В шаблон» в меню операции).

Цель: **≤ 5 секунд** от открытия до сохранения; для шаблона — **1 тап + «Сохранить»**.

### Сценарий 2. «Голосом на ходу» — 1 нажатие + фраза

```
[Action Button] → «Добавь расход» → 🎤 «кофе двести пятьдесят»
→ сервер парсит → уведомление «Записано: Кофе · 250 ₽» [Отменить]
```

- Шорткат: `Dictate Text` → `Get Contents of URL` (POST `/api/ingest/text`) → `Show Notification` с ответом сервера.
- Сервер: нормализует числительные, ищет сумму, сопоставляет категорию по словарю, подставляет последний счёт.
- Если не понял сумму — не создаёт ничего, возвращает «Не понял сумму».
- Если понял сумму, но не категорию — создаёт с «Другое» и `needs_review`.
- В приложении такая операция помечена значком «распознано».

### Сценарий 3. «SMS пришло само» — 0 действий (опция 99 ₽/мес)

```
SMS от Т-Банка → автоматизация Shortcuts → POST /api/ingest/sms
→ сервер парсит → операция создана → push «Записано 250 ₽ · Пятёрочка»
```

- Если уверенность низкая → операция в «Требует проверки», на иконке бейдж.
- Дубль с ручной операцией → «Возможный дубль», обе видны, выбор пользователя.
- Формат SMS неизвестен → сырой текст сохраняется в «Инбокс», ничего не создаётся молча.

### Сценарий 4. «Проверка кредитки»

```
Главная → блок кредитки → «Выписка 29.11 → оплатить до 22.12»
→ «Сумма не указана» [Уточнить] → ввод суммы → сохранили
```

- Пока сумма неизвестна, блок выделен жёлтым и говорит об этом.
- После ввода — «Осталось 12 дней», прогресс погашения.
- Платёж: «Погасить» → выбор счёта-источника → сумма → сохранение.
- Погашение **не** создаёт расход; в аналитике видно «долг уменьшился».

### Сценарий 5. «Флешка: выручка 2 000, себестоимость 700»

```
Подработки → «Новая продажа» → название «Флешка 64 ГБ»
→ выручка 2 000 → себестоимость 700 → сохранить
```

Результат: проект «Флешка 64 ГБ», прибыль **1 300 ₽**, две связанные операции (доход + расход с `project_id`). В списке проектов — маржа и статус.

Если оплата ещё не пришла: статус «Ожидает оплаты», сумма в «Ожидаемые поступления», но **не** в балансе.

### Сценарий 6. «Пенсия 23-го»

- Регулярная операция: 13 000 ₽, окно 21–31, счёт «Т-Банк Black».
- 21-го появляется карточка «Пенсия ожидается 21–31 ноября» с кнопкой «Пришла».
- Одно нажатие → операция создана на сегодня, карточка исчезает.
- Если не нажали до 31-го — карточка остаётся, но не спамит push.

### Сценарий 7. «Месячная сверка»

```
ПК → сайт Т-Банка → CSV → приложение → «Импорт»
→ предпросмотр (новые / дубли / неизвестные) → «Импортировать 12»
```

- Дубли определяются по дате+сумме+описанию.
- Неизвестные категории — «Разобрать позже».
- После импорта — «Баланс совпал» или «Расхождение 340 ₽» с разбором.

### Сценарий 8. «Сколько можно потратить»

```
Главная → «Безопасно сегодня: 420 ₽»
→ тап → водопад: доход → обязательные → кредит → резерв → свободно
```

Показывает не магическое число, а арифметику. Если свободно ≤ 0 — «Дефицит 1 200 ₽», и что можно срезать.

### Сценарий 9. «Шаблон за один тап»

```
Главная → чип «Проезд 60 ₽» → готово
```

- Тап по чипу создаёт операцию с сохранёнными суммой, счётом и категорией.
- Тост «Записано · 60 ₽ · Транспорт» с «Отменить».
- Долгое нажатие на чип → «Изменить шаблон» / «Удалить».
- Если шаблон устарел (сумма изменилась) — обычный ввод: сумма → категория → сохранить.

### Сценарий 10. «Можно ли купить за 3 500 ₽»

```
Помощник → «Оценка покупки» → 3 500 ₽ → счёт «Т-Банк Black»
→ «Рискованно: останется 320 ₽ до пенсии, платёж по кредитке не подтверждён»
```

- Вердикты: «Можно», «Рискованно», «Не стоит».
- Всегда показывает последствия: остаток, дни до дохода, что придётся отложить.
- Если платёж по кредитке неизвестен — это явно называется, а не подставляется ноль.
- Оплата кредиткой не делает покупку «доступной»: лимит не считается доходом.

### Сценарий 11. «Пришла подработка 4 000 ₽»

```
Помощник → «Распределить 4 000 ₽» → водопад:
кредитка 1 500 → резерв 1 000 → продукты 1 000 → свободно 500
```

- Приоритеты: просроченный/ближайший платёж по кредитке → пополнение резерва → обязательные расходы → накопления.
- Каждая строка с причиной; сумму можно изменить вручную.
- Подарок или «возможное» поступление сюда не попадает, пока не стало фактической операцией.

## 4. Карта экранов

```
/                     Главная (баланс, безопасно тратить, последние операции)
/add                  Быстрый ввод (bottom sheet)
/operations           Все операции + фильтры + поиск
/operations/:id       Детали, редактирование, история
/accounts             Счета
/accounts/:id         Счёт (для кредитки — расширенный)
/credit               Кредитка: выписки, платежи, прогноз
/budget               Бюджет: план/факт, водопад
/assistant            Финансовый помощник: безопасно тратить, прогноз, покупка, распределение
/analytics            Аналитика: периоды, категории, динамика
/jobs                 Подработки (проекты)
/jobs/:id             Проект: выручка, затраты, прибыль
/goals                Цели
/settings             Настройки
/settings/security    Passkey, устройства, сессии, коды, блокировка
/settings/data        Экспорт, импорт, бэкапы
/settings/categories  Категории
/settings/recurring   Регулярные операции
/settings/templates   Шаблоны быстрого ввода
/setup                Первичная настройка
/login                Вход
```

Нижняя навигация (iPhone): **Главная · Операции · [+ ] · Помощник · Ещё**.
На десктопе: боковая панель + горячие клавиши (`N` — новый расход, `/` — поиск, `G` затем `H` — главная, `L` — заблокировать).


> Цифры в макетах иллюстративные и показывают более поздний период, а не стартовые балансы. Стартовые данные (наличные 5 000 ₽, дебет 4 000 ₽, долг 41 000 ₽) — в `ARCHITECTURE.md` §14.

Правила:
- «Свободно» = только свои деньги. Кредитный лимит сюда не входит.
- Кредитка — отдельный блок с предупреждением, если дата близко или сумма неизвестна.
- «Ожидается» — пунктирная рамка, не входит в баланс.
- Шаблоны — один тап создаёт операцию.
- Суммы — `tabular-nums`, выровнены вправо.

- Долгое нажатие на категорию → выбор подкатегории.
- Свайп вниз — закрыть без сохранения (с подтверждением, только если сумма > 0).
- «Сохранить» всегда в правом нижнем углу, высота 52.

```
┌─────────────────────────────────┐

│  [Все] [Расход] [Доход] [Перевод]│
```

- Группировка по дням, итог дня.

- Свайп по строке: влево — удалить (undo), вправо — редактировать.
- Долгое нажатие — контекстное меню: «Дублировать», «В шаблон», «История».

```
│  Кредитка                       │
│  ⚠️ Сумма платежа не указана    │
│  [ Уточнить ]                   │
│                                 │
│  Можно ли купить?               │
│  [ 3 500 ₽ ]  [ Проверить ]     │
│                                 │
│  Пришло 4 000 ₽                 │
│  [ Распределить ]               │
└─────────────────────────────────┘
```

Раскрытие «Как посчитано?»:

```
Свободно = ликвидные − резерв − известные платежи
= 9 000 − 2 000 − 0 = 7 000 ₽
Дней до пенсии: 10
7 000 / 10 ≈ 700 ₽/день
Но платёж по кредитке неизвестен → осторожная оценка 420 ₽
```

Правила:
- Любая цифра раскрывается до формулы и входных данных.
- Неподтверждённые поступления помечены и не входят в расчёт.
- Неликвид (Steam) не участвует.
- Кредитный лимит не участвует.
- Если платёж неизвестен — честное предупреждение и снижение уверенности, а не ноль.

### 7.1. Блокировка приложения

| Событие | Поведение |
|---|---|
| Открытие приложения | Не блокирует, если прошло меньше таймаута |
| Уход в фон | Запоминает время, но не показывает промпт |
| Возврат через 20 минут | Оверлей «Заблокировано», данные не отрисованы |
| Возврат через 2 минуты | Работает сразу, без Face ID |
| Кнопка «Заблокировать» | Блокирует немедленно |
| Настройка | 5 / 15 / 30 / 60 минут / никогда |

- Разблокировка — кнопка «Разблокировать» (WebAuthn, Face ID). Автозапуск промпта запрещён: iOS требует жеста, а самопроизвольный промпт выглядит как сбой.
- Если Face ID отменён или недоступен — «Войти заново» и «Код восстановления».
- Пока экран заблокирован, содержимое приложения **не рендерится** (не просто размывается).
- Это UI-замок, а не шифрование кэша. Так и написано в настройках.
- Таймер проверяется при возврате в приложение: на iOS нет фоновых таймеров, и это ожидаемо.

## 9. Онбординг

1. **Приветствие** — 3 экрана: что это, как ставится на iPhone, что данные только у вас.
2. **Passkey** — «Создать ключ доступа» (Face ID). Сразу предложить второй на Windows: «Добавьте ключ на втором устройстве, иначе потеря телефона закроет доступ».
3. **Коды восстановления** — показать, скачать, подтвердить «Сохранил». Без этого шага нельзя закрыть онбординг.
4. **Стартовые балансы** — по одному экрану на счёт, с датой и пометкой «введено вручную».
5. **Кредитка** — лимит, долг, дата выписки, дата платежа. Сумма платежа — «уточню позже».
6. **Доход** — пенсия 13 000, окно 21–31. Подработки — «добавлю по факту».
7. **Бюджет** — 6 000 ₽, метка «предварительный ориентир, не гарантия».
8. **Блокировка** — «Спрашивать Face ID после 15 минут бездействия?» (по умолчанию да).
9. **Установка** — инструкция для iOS и Windows.
10. **Готово** — «Безопасно сегодня: …» (может быть отрицательным — это честно).

Пропустить можно любой шаг, кроме passkey и кодов восстановления. Всё потом редактируется.

> В локальной разработке вместо домена используется `http://localhost:5173`. Passkey, созданный для `localhost`, **не переносится** на production-домен: после переезда нужен вход по коду восстановления и новый passkey. Это ожидаемое поведение, а не ошибка.

## 12. Что проверить на реальном iPhone

1. Открытие листа быстрого ввода при активной клавиатуре — не прыгает ли layout.
2. Нижняя навигация не перекрывается home-indicator.
3. Ввод суммы одной рукой — достаёт ли большой палец до «Сохранить».
4. Офлайн: создать операцию в самолётном режиме, закрыть, открыть, включить сеть.
5. Установка: сессия сохраняется после «На экран Домой».
6. Push после установки.
7. Тёмная тема при системной.
8. Долгий список операций — плавность скролла.
9. Share sheet для экспорта файла.
10. Голосовой шорткат с Action Button.
11. Блокировка: уйти в фон на 20 минут → вернуться → оверлей, Face ID, данные появились.
12. Шаблон: тап по чипу на главной создаёт операцию; Undo возвращает.
13. Второй passkey: вход с Windows, затем удаление ключа iPhone не блокирует доступ.
14. Вход по коду восстановления: код сгорает, новый passkey создаётся.
15. `npm run backup` + `npm run verify-backup` на ПК: архив читается, таблицы на месте.
